# 分部写作 Playbook（摘要 / 引言 / 结果 / 讨论 / 图注 / Cover letter）

> 用法：写或改任一部分前，先读对应小节；交付前跑该节的**自检清单**。
> 统计基线凡标 `W39 实测` 者来自 50 篇 INTRO/IMRAD 扫面（详见 `imrad-anatomy-protocol.md` §六）；标 `[待复算]` 者尚未统计，**不得当基线引用**。

---

## 0. 跨节对齐（先定这个，再写任何一节）

任何一节都不能单独写好。**四句必须先钉死，全文围绕它们展开**：

| 锚句 | 内容 | 位置 | 下游依赖 |
|---|---|---|---|
| **G 句（gap）** | 前人未解决/未检验/结论冲突的那一句 | Intro 末段或倒数第二段末 | Results 每段至少回应一次；Discussion 首段回指 |
| **A 句（approach）** | 针对 G 句，本文做了什么设计 | Intro 末段最后 1–2 句 | Methods 必须逐项对应；不能出现 A 句未提的关键设计 |
| **F 句（finding）** | 主结论（1 句，含方向） | Abstract 结果句、Discussion 首句 | Abstract 与 Discussion 首句必须**同向同强度** |
| **C 句（contribution）** | 把 F 句推到领域层面：改变了什么判断 | Discussion 倒数第二段 | 不得超出 F 句的证据边界 |

**对齐检查（强制）**：写出四句 → 逐项问“G 句提到的缺口，Results 里哪张图回答？A 句提到的设计，Methods 里有没有？”任一项答不出即停下改结构，不要先润色文字。

## 1. 摘要（Abstract）

### 功能
让读者在 30 秒内能判断“要不要读全文”。**不是引言的压缩版**，是全文的**结论前置版**。

### 槽位模板

| 槽位 | 句数 | 必须写 | 禁止写 |
|---|---|---|---|
| S1 背景收口 | 1 | 具体对象+具体后果（最好带数字） | `In recent years...has attracted attention` |
| S2 缺口 | 1 | 可检验的未知（whether / remains unclear / has not been tested） | `Few studies have...`（空泛） |
| S3 方法 | 1–2 | 设计类型+对象/样本量+关键手段 | 罗列所有软件与参数 |
| S4 结果 | 2–4 | **3 个方向明确的数字**（效应量+统计量+n） | `significant`、`dramatic` 等无数字形容 |
| S5 意义 | 1 | 对**哪个具体判断**的修正 | `provides new insights` / `lays a foundation` |

字数配比 `[待复算]`：结构化摘要按期刊小标题写；非结构化多数把 **S4 占 40–50%**。

### 句式骨架
- 缺口：`Whether <可检验命题> in <对象> remains unknown.`
- 方法：`We <动词> in <n> <对象> using <手段>, with <对照/验证>.`
- 结果：`<指标> <动词过去式> from <A> to <B> (<统计量>, P = <值>, n = <n>).`
- 意义：`These data identify <对象> as <具体角色> in <具体过程>.`

### 真人 vs AI

| AI 常写 | 真人写法 |
|---|---|
| 背景 2–3 句铺陈 | 背景 1 句，直接给规模/负担数字 |
| 结果句用 `significantly improved` | 给效应量与 P 值 |
| 末句 `provides valuable insights` | 指向一个可被后续研究检验的判断 |
| 五槽等长 | 结果槽明显最长 |

### 自检
- [ ] S4 有 ≥3 个数字，且每个数字能对到正文某图
- [ ] S5 不含 `novel` / `insight` / `foundation` / `promising`
- [ ] 摘要与 Discussion 首句同向同强度（不许摘要强、讨论弱）
- [ ] 缩写首次出现即定义，之后全篇统一

## 2. 引言（Introduction）——漏斗四步法

### 功能
把一个**领域级的模糊关切**压缩成一个**本文能回答的具体问题**。四步是**认知台阶**，不是四段话；可以写在 3 段里。

### 四步法（先生 2026-10-18 指定的范例）

| 步 | 名称 | 句数 | 要做什么 | 判据（不合格即重写） |
|---|---|---|---|---|
| **①** | **大背景收口** | 1–2 句 | 用一两句话点出领域现状，**别扯太远** | 每句都必须被后文“用得上”；删掉后第②步仍成立 = 该句多余 |
| **②** | **聚焦前沿** | 2–4 句 | 挑**最有代表性**的文献，说清别人做出了什么成果 | 每篇文献一句一个动作（`X was shown to Y in Z`）；不写“许多研究” |
| **③** | **找 gap（最重要）** | 1–2 句 | 前人**没解决什么**、或**需要改进什么** | gap 必须是**可被本文结果回答**的；必须能指出“不知道会损失什么” |
| **④** | **抛出本研究** | 1–2 句 | 针对该 gap，我做了什么、有什么意义 | 动作与 gap 一一对应；不预告未做的实验；不写“具有重要意义” |

### 第②步的选文三标准（3C）

| 标准 | 含义 | 操作 |
|---|---|---|
| Closest | 与本课题问题最接近 | 优先引“同一模型/同一人群/同一通路”的工作 |
| Strongest | 证据等级最高 | 同题优先引大样本、随机、金标准方法 |
| Most recent | 最近 2–3 年 | 用来证明“这是当前前沿”，不是用来凑数 |

**②的失败形态**：把 10 篇文献堆成“A 发现…B 发现…C 发现…”，读者读完不知道该信谁。**正解**：按“结论分组”而非按“文献罗列”——`一致的一组 → 留下未解释的差异 → 差异即缺口`。

### 第③步的 gap 五型（选一，不要混着写）

| 型 | 缺口表述 | 本文能接的答法 |
|---|---|---|
| G1 证据缺口 | 某对象/人群从未被检验 | 首个验证（须说明为何此前做不到） |
| G2 机制缺口 | 现象已知，通路未知 | 上下游实验 + 回补 |
| G3 人群缺口 | 结论只在外推人群成立 | 分层/独立队列 |
| G4 方法缺口 | 现有方法有系统性偏倚 | 新方法 + 与金标准一致性 |
| G5 矛盾缺口 | 两项结论冲突 | 找出区分变量并检验 |

**G5 是最高分也最难写的**：不得只写“存在争议”，必须写出**可检验的区分假设**（`若差异源于剂量，则低剂量组应复现 A 的结论`）。

### 第④步的两种合法写法

- 陈述型（保守，适合机制论文）：`Here we tested whether <G 句命题> by <设计>.`
- 结论前置型（适合高影响刊）：`Here we show that <方向性结论>, and that this depends on <机制>.` —— 前提是主图已能支撑，不得虚张。

### 段数与句长基线（W39 实测，50 篇 / 31 篇可得引言）

| 指标 | 基线 |
|---|---|
| 句长均值 | **24.2 词**（SD 8.9） |
| ≤15 词短句 | 16.7% |
| ≥35 词长句 | 12.2% |
| 每段句数中位 | **5** |

→ 引言是**论证章**，句子偏长、短句少；与 Results（21.0 词 / 33.7% 短句）形成对照，**不要写成一样的节奏**。

### 自检
- [ ] 倒读测试：从 G 句往前读，每一步是否**必要**？删任一句是否塌？
- [ ] G 句能否被 Results 中**至少一张图**回答？
- [ ] ②里的每篇文献是否真的支撑“别人做出了什么”，而不是“别人也研究过”？
- [ ] 有没有出现 `increasing attention` / `plays a crucial role` / `delve into`
- [ ] 末句是否只承诺**本文做过**的事

## 3. 结果（Results）

### 功能
按**论证顺序**（不是图表顺序）逐层关闭 G 句的各个子问题。

### 段落模板（每段 = 一个 claim）

| 位置 | 内容 | 字数 |
|---|---|---|
| 主题句 | 本段结论，含方向（`X reduced Y`） | 1 句 |
| 支撑 | 关键数值 + 统计量 + n；只写结论性数字 | 2–4 句 |
| 边界句 | 该结论的适用范围/条件（部分论文写） | 0–1 句 |
| 过渡 | 指向下一段要解决的问题 | 0–1 句 |

### 叙事序列的四种范式

| 范式 | 适用 | 序列 |
|---|---|---|
| 表型→机制→干预 | 机制类 | 现象 → 通路 → 阻断验证 |
| 发现→验证→外推 | 组学/生信 | 筛选 → 独立队列验证 → 临床关联 |
| 分层递进 | 临床 | 总体 → 亚组 → 交互 |
| 正交三角 | 方法/结构 | 方法 A、B、C 各自独立指向同一结论 |

### 子标题句法（W39 实测）
Results 子标题 **17% 为论断句**（204 个中 35 个），且有 IF 梯度（`>10` 53%）。→ **高分区允许把结论写进子标题**，低分区一律名词短语。

### 真人不会做的事
- 不复述图表全部数字（只给支撑 claim 的那几个）
- 不在 Results 里解释机制（留给 Discussion）
- 不用 `Interestingly` / `Notably` 开头超过 1 次
- 不隐去阴性结果；阴性结果单独成句并给数值

### 自检
- [ ] 每段第一句是否**已经是结论**（而不是“为了探究…我们做了…”）
- [ ] 每个数字是否在图中可定位
- [ ] 是否存在“结果段里做机理解释”的越界句
- [ ] 阴性结果是否被写成“未见差异”而非省略

## 4. 讨论（Discussion）

### 功能
把 Results 的碎片重新组装成**一个可被引用的知识单元**，并交代它的边界。

### 六段链（W39 主流，53 个 D 章）

| 段 | 功能 | 首句要求 |
|---|---|---|
| D1 | 主要发现复述（1 段，不重复数字细节） | 回指 F 句，**同向同强度** |
| D2 | 与文献横向对比（一致的一组） | `Consistent with <文献>, we found ...` |
| D3 | 不一致之处及解释（**必须写**，无则说明为何无） | `In contrast to <文献>, ...` + 可能原因（人群/剂量/模型/统计口径） |
| D4 | 机制解释（可合并进 D2/D3） | 用本文数据支持的部分，其余标 `plausibly` |
| D5 | 优势与局限（一整段，不是一句免责） | 局限段**平均 9.7 句**（W39），是全文最长段之一 |
| D6 | 展望（可执行） | 给出“下一步要做什么、需要什么条件” |

### 局限段写法（W39 实测）
- **91%** 的论文把局限写在 Discussion 正文段落里；独立 `Limitations` 小标题仅 **3%**。
- 一条局限的合格结构：`局限是什么 → 为什么它削弱了哪个结论 → 我们做了什么缓解 / 读者应如何打折`。
- **禁止**：`Our study has several limitations` 之后列三条不痛不痒的客套（样本量小、单中心、需进一步验证）。这三条属于“通用免责”，不算局限。

### 真局限 vs 客套局限

| 真局限（会削弱结论） | 客套局限（不削弱） |
|---|---|
| 相关设计无法排除反向因果 | 样本量偏小（若已给功效计算则不算） |
| 只在一种模型验证，外推受限 | 未做多中心（若本文非临床研究则无关） |
| 干预剂量高于生理浓度 | 需要更多机制研究 |
| 随访不足以观察终点事件 | 结果需进一步验证 |

### 自检
- [ ] D1 首句与 Abstract 末段结论是否**强度一致**
- [ ] 是否写了**不一致**的文献；若确实没有，是否说明检索范围
- [ ] 局限段是否 ≥5 句，且至少 1 条是“真局限”
- [ ] 展望是否可执行（含对象、设计、条件），不是 `future studies are warranted`
- [ ] C 句（贡献）是否超出 F 句证据边界

## 5. 图注（Figure legends）

### 功能
让图**脱离正文独立可读**。审稿人先看图注，再决定是否看图。

### 结构（四段式）

| 段 | 内容 | 长度 |
|---|---|---|
| L1 标题 | **名词短语**，说明这张图证明什么 | W39 实测：首句平均 **17.7 词**，**60% ≤12 词**；不用 `This figure shows that...` |
| L2 分图描述 | `(A) ... (B) ...` 每 panel 一句，含处理条件与读数 | 每 panel 1 句 |
| L3 统计与样本 | 检验方法、n、误差棒含义、显著性标记定义 | 1–2 句 |
| L4 缩写与来源 | 未在正文定义者；数据来源/scale bar | 0–1 句 |

### 句式骨架
- 标题：`<对象> <动词过去式> <效应> in <条件>.`（省主语，不用完整句）
- panel：`(A) Representative <方法> images of <对象> treated with <条件>. Scale bar, <n> μm.`
- 统计：`Data are mean ± s.d. (n = <n> biologically independent samples); two-tailed t-test.`

### 常见错误
| 错误 | 后果 |
|---|---|
| 标题写成 `Effects of X on Y` | 读者不知道结论方向 |
| panel 描述只写处理、不写读数 | 图注失去自明性 |
| 统计信息写在正文而不在图注 | 图脱离正文不可读 |
| 显著性星号未定义 | 审稿人直接质疑 |
| 图注与正文数字不一致 | 最常被抓的硬伤 |

### 自检
- [ ] 遮住正文，只看图注能否判断这张图证明了什么
- [ ] 每个 panel 都有对应描述，无遗漏、无多余
- [ ] 图注中的 n、检验方法、误差棒与 Methods 完全一致
- [ ] 星号/符号有定义；缩写首次出现处有全称

## 6. Cover letter（投稿信）

### 功能
**不是摘要复述**，是替编辑做三件事：判断是否在 scope 内、判断是否值得送审、判断有没有伦理与竞争风险。

### 结构（1 页，300–450 词）

| 段 | 内容 | 字数 |
|---|---|---|
| P1 投稿声明 | 稿件题目、类型（Original article / Brief communication）、声明未一稿多投 | 40–60 |
| P2 问题与缺口 | 领域现状 1 句 + G 句（**用编辑能懂的写法，少术语**） | 80–100 |
| P3 核心发现 | 2–3 个具体结果（带数字），一句一个 | 80–120 |
| P4 为何适合本刊 | 与本刊近 2 年发表的 2–3 篇具体论文衔接（给题目或作者+年），说明本文如何推进 | 60–100 |
| P5 合规声明 | 伦理批号、数据可得性、利益冲突、作者贡献与全体同意、是否预注册 | 40–60 |
| P6 收尾 | 一句，不写恭维 | 15–25 |

### 禁忌（编辑一眼能看出群发）
- 复制摘要前两句当开头
- `We are pleased to submit our manuscript entitled...` 之后紧跟摘要全文
- 通篇 `novel` / `significant` / `high impact` 却不给数字
- 没提本刊任何一篇具体论文（说明没读刊）
- P5 缺失伦理或数据可得性声明（直接退稿的常见原因）

### 自检
- [ ] 是否点名本刊近 2 年 ≥2 篇具体论文
- [ ] 核心发现是否 ≥2 个数字
- [ ] 是否出现 `novel` / `groundbreaking` / `first time`（未核不写）
- [ ] 伦理批号、数据可得性、COI、作者同意四项齐全
- [ ] 全文 ≤1 页；无中译英痕迹（`study on` / `the reason is because`）

## 7. 各部分联动的三条硬规则

1. **G 句唯一**：全文只允许一个主缺口。出现第二个 gap 时，它必须降级为 Results 的一个子问题。
2. **强度守恒**：Abstract 的结果强度 = Results 主题句强度 = Discussion D1 强度。任一处拔高或压低都是缺陷。
3. **数字守恒**：同一指标在 Abstract、Results、图注、Discussion 中的数值必须完全一致；小数位也一致。

交付前跑 `scripts/term_consistency.py` 与 `references/ai-trace-remediation.md` 三步检查。
